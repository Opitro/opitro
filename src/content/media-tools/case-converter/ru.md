В snake_case всё строчными, слова разделены подчёркиванием: my_variable_name. Разные языки держатся разных привычек: в JavaScript принят camelCase, в Python — snake_case, и при переносе кода из одного в другой имена приходится переписывать пачками."

UPPER_CASE пишет всё заглавными через подчёркивание: MY_VARIABLE_NAME. Так по традиции объявляют постоянные значения, которые не меняются во время работы программы."

Вставьте список имён — по одному в строке. Результат появится сразу.

## Пять стилей

- **camelCase** — `userFirstName`, принят в JavaScript
- **PascalCase** — `UserFirstName`, для классов и типов
- **snake_case** — `user_first_name`, принят в Python и в базах данных
- **kebab-case** — `user-first-name`, для классов CSS и адресов страниц
- **UPPER_CASE** — `USER_FIRST_NAME`, для постоянных значений

## Три места, где ломается наивное правило

**Аббревиатуры.** По правилу «заглавная начинает слово» `parseHTTPResponse` стало бы `parse_h_t_t_p_response`. На деле из череды заглавных последняя уходит к следующему слову: получается `parse_http_response`.

**Цифры.** `user2Name` — это `user2` и `Name`, а не три части. Выходит `user2_name`.

**Подчёркивания по краям.** В Python `__init__` и `init` — разные имена. Края остаются как были при любом стиле.

## Список возвращается готовым к вставке

Отступы и хвостовые запятые сохраняются: строка `  userName,` станет `  user_name,`. Список можно вернуть в код, ничего не подправляя.
